# Connect the lab to God's Eye View and Astra

![Evidence workflow](assets/evidence-workflow.svg)

JupyterLite computes and exports. Leaflet/Cesium viewers display the same fictional layer. An adapter loads it into a separate God's Eye View instance. Optional local Python sends bounded evidence to Astra and validates its response. No secret belongs in public notebooks, HTML or a Pages build.

## Install the upstream layer adapter

Original code: [`integrations/gods-eye-view/training-layer.js`](https://github.com/jltobias/JupyterLite-Gods-Eye-View-Satellite/blob/main/integrations/gods-eye-view/training-layer.js). It adds local-file selection, show/hide, removal, size limits, coordinate checks, synthetic labels and teardown. It does not send notebook data to a server or register a telemetry feed.

The installation point was inspected at upstream [`e7707d9a0f34d9fbffc300023c319f95caa5be30`](https://github.com/bilawalsidhu/gods-eye-view/tree/e7707d9a0f34d9fbffc300023c319f95caa5be30). Its scene exposes `viewer` and a lifecycle `defer` callback. This is a source-level extension, not a stable plugin API promise. The full upstream feed stack is outside this repository's tests.

1. Set up a **separate local checkout** using the [upstream README](https://github.com/bilawalsidhu/gods-eye-view); respect its Node version and provider terms.
2. Copy the adapter to `src/training-layer.js` there.
3. In `src/standalone/application.js`, add:

```javascript
import * as Cesium from 'cesium';
import { mountTrainingLayer } from '../training-layer.js';
```

4. In `createScene`, after `const scene = await createStandaloneScene(...)` and before `return scene`, register:

```javascript
context.defer(mountTrainingLayer({ viewer: scene.viewer, Cesium }));
```

5. Start upstream. Download notebook 12's `riverbend-analysis.geojson` and choose it in **JupyterLite · SYNTHETIC EXERCISE**. Verify show/hide/removal and preserve provider credits.

Turn off unrelated live layers for clarity if desired. The training overlay is not a current observation. Remove the imports and registration to uninstall; upstream datasets remain independent.

## Timed CZML

The picker accepts **GeoJSON**. For trusted CZML generated by notebook 12, a developer can load it in the same scene callback:

```javascript
// Place the generated file in public/training/ in the upstream checkout.
const route = await Cesium.CzmlDataSource.load('/training/riverbend-route.czml');
await scene.viewer.dataSources.add(route);
context.defer(() => scene.viewer.dataSources.remove(route, true));
```

Upstream owns its clock. Review clock behavior before copying a document clock into it; replacing live time can misalign other feeds. Notebook 09's standalone scene already has an isolated exercise clock, play/pause and scrubber.

## Astra integration

Model ID **`gpt-6-astra`** was checked against [official documentation](https://developers.openai.com/api/docs/models/gpt-6-astra) on **2 October 2026**. The example uses Responses, strict structured output and optional image input. General reasoning, coding, image analysis and tool use support geospatial work; they do not replace a GIS engine or verified epidemiologic analysis.

| Workflow | Demonstrated | Further deployment work |
|---|---|---|
| Evidence synthesis | Aggregate packet → structured briefing | Authorized live ingestion |
| Visual reasoning | Optional PNG/JPEG with computed evidence | Evaluation across real products/resolutions |
| Coding/QA | Numerical invariants, coordinates, citation rejection | Controlled execution and review of generated code |
| Research/tools | Citation contract and verification prompts | Authenticated retrieval/tool broker |
| Multilingual briefing | Exercise prompt and review rubric | Local-language validation |

Download the evidence packet from 10 and run locally:

```bash
python tools/astra_brief.py --input evidence-bundle.json --output request.json
# Dry run above. Set OPENAI_API_KEY in the local process, then opt in:
python tools/astra_brief.py --input evidence-bundle.json --output briefing.json --live
```

Optionally add `--image map.png`. The CLI defaults to no network, rejects extra record fields, checks totals/rates and input size, and requires `synthetic: true`. It never prints the key or overwrites outputs. Live calls need model access and incur usage. The book and CI do not make them.

Schema checks and source-ID validation **do not prove a claim is true**. Review facts, dates, numbers, limits and proposed steps. The deterministic fixture is not model output. Live results include a separate metadata file with response ID, model and usage.

References: [Responses](https://developers.openai.com/api/docs/guides/text), [structured output](https://developers.openai.com/api/docs/guides/structured-outputs), [image limitations](https://developers.openai.com/api/docs/guides/images-vision), [data controls](https://developers.openai.com/api/docs/guides/your-data).
